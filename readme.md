# RAG Document Question-Answering Project

## Project Goal

The goal of this project is to build a Retrieval-Augmented Generation (RAG) system that can answer questions based strictly on the contents of a set of documents, rather than relying on a language model's general knowledge.

The system is designed to:

- Ingest PDFs
- Store their contents in a searchable vector database
- Retrieve relevant document sections for a given question
- Use a local LLM to generate grounded, context-aware answers

This approach reduces hallucinations and makes answers traceable back to the source documents.

## Experiment: Comparing RAG Approaches

This project includes an experiment comparing three prompting strategies:

| Approach | File | Description |
|----------|------|-------------|
| **Baseline** | `query.py` | Simple context + question prompt |
| **Chain of Thought** | `query_cot.py` | Adds step-by-step reasoning before answering |
| **CoT + Citations** | `query_cot_cite.py` | Reasoning + source attribution with `[Source N]` notation |

Run the experiment:
```bash
python run_experiment.py
```

Results are saved to `experiment_results.txt`.

## High-Level Overview

This project follows a standard RAG pipeline:

1. Documents are loaded and split into chunks
2. Each chunk is embedded into a vector
3. Vectors are stored in a vector database
4. User questions are embedded
5. Relevant document chunks are retrieved via similarity search
6. A language model answers the question using only the retrieved context

No fine-tuning is used. All intelligence comes from retrieval + prompting.

## Technologies Used

### Core Stack

- Python 3.11
- LangChain
- ChromaDB (vector store)
- Ollama
  - `nomic-embed-text` for embeddings
  - `llama3.2` for text generation

### Optional / Intended

- AWS Bedrock embeddings (e.g., Titan)
  - Bedrock embeddings generally provide better retrieval quality than local Ollama embeddings

## File-by-File Explanation

### `embed.py`

Defines one embedding function used everywhere in the project.

Why this matters:
- Embeddings used for indexing must match embeddings used for querying
- Mixing models silently breaks retrieval

Current setup:
```python
OllamaEmbeddings(model="nomic-embed-text")
```

This file exists to ensure consistency and make future swaps (e.g., Bedrock) easy.

### `load.py` — Indexing Step

This script:
1. Loads PDFs from `pdfs/`
2. Splits text into chunks
3. Embeds each chunk
4. Stores embeddings + metadata in ChromaDB

Metadata stored per chunk:
- `source`: file path (e.g., `pdfs/tech_ops.pdf`)
- `page`: page number
- `id`: unique identifier (`source:page:chunk_index`)

Run once per document change or embedding model change:
```bash
python load.py          # Add new documents
python load.py --reset  # Rebuild from scratch
```

### `query.py` — Baseline RAG

Simple RAG pipeline:
```bash
python query.py "What problems exist with current documentation?"
```

Steps:
1. Embed the user's question
2. Retrieve top-5 relevant chunks from ChromaDB
3. Construct prompt with context + question
4. Pass to `llama3.2`
5. Return the answer

### `query_cot.py` — Chain of Thought

Same as baseline, but the prompt asks the LLM to reason step-by-step:

```
Before answering, think through:
1. What information in the context is relevant?
2. What reasoning connects context to answer?
3. Are there gaps or uncertainties?

Reasoning: <step-by-step>
Answer: <final answer>
```

```bash
python query_cot.py "What problems exist with current documentation?"
```

### `query_cot_cite.py` — Chain of Thought + Citations

Adds source tracking:
- Each context chunk is labeled `[Source N]` with filename and page
- Prompt instructs LLM to cite sources in the answer
- Returns structured data with answer + source metadata

```bash
python query_cot_cite.py "What problems exist with current documentation?"
```

Example output:
```
Question: What problems exist with current documentation?

Answer:
Reasoning: Source 1 mentions clarity issues, Source 3 discusses outdated info...

Answer: Documentation has clarity problems [Source 1] and contains
outdated information [Source 3].

Sources:
  - Source 1: tech_ops_review.pdf, Page 5, Chunk: pdfs/tech_ops_review.pdf:4:0
  - Source 3: tech_ops_review.pdf, Page 12, Chunk: pdfs/tech_ops_review.pdf:11:2
```

### `runAll.py` — Test Harness

Runs the same questions through all three approaches:

```bash
python runAll.py
```


Results saved to `experiment_results.txt` for comparison.

## How Citation Tracking Works

No additional embedding required. Citations use metadata already stored in ChromaDB:

```
ChromaDB stores per chunk:
┌─────────────────────────────────────────────────┐
│ content: "Documentation lacks structure..."     │
│ metadata: {source: "pdfs/tech.pdf", page: 4}   │
│ embedding: [0.12, -0.34, 0.56, ...]            │
└─────────────────────────────────────────────────┘
         ↓
query_cot_cite.py formats as:
         ↓
"[Source 1] (from tech.pdf, Page 5): Documentation lacks structure..."
         ↓
LLM sees label → cites in answer → we display source metadata
```

## Issues Encountered & Resolved

### Python 3.14 Compatibility
- Python 3.14 caused multiple dependency and tooling issues
- Migrated to Python 3.11, which resolved these issues

### LangChain Import Changes
- `langchain.vectorstores.*` → removed
- Vector stores moved to `langchain_chroma`
- Community integrations moved to `langchain_community`

### Ollama Deprecation Warnings
- Ollama classes deprecated in LangChain core
- Migrated to `langchain-ollama` package

## Why RAG Was Chosen

RAG was chosen because:
- Documents change frequently
- Fine-tuning is expensive and inflexible
- Answers need to be grounded in source material
- Errors must be traceable

This architecture allows:
- Swapping models without retraining
- Updating documents without retraining
- Inspecting and debugging failures

## Mental Model

```
Documents → split into chunks
Chunks → embeddings
Embeddings → vector store
Question → embedding
Similarity search → relevant chunks
Prompt → context + question
LLM → answer
```

If answers are bad, the issue is usually:
- Embeddings
- Chunking
- Retrieval
- Prompt design
